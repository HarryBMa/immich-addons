# Wiring auto-lut to Immich

auto-lut can be driven two ways. **Start with polling.** It depends only on the stable REST API, so
it keeps working across Immich upgrades. Add the webhook once polling is proven, for lower latency.

> Workflows is a **preview** feature in Immich v3. Its webhook payload shape is not guaranteed and
> has no compatibility promise. Everything in the webhook section below may need adjusting after an
> upgrade — the fallback is always: set `TRIGGER_MODE=poll` and carry on.

## Before either path

1. Put a `.cube` file in `/data/luts` (the three shipped ones are in `fixtures/luts`, generated by
   `scripts/make_luts.py`).
2. In the hub, open **auto-lut → Configure**, pick the LUT, set the intensity, and **leave
   `dry_run` on**.
3. Run it once and read the job log. Dry run performs the whole pipeline — download, grade, EXIF
   copy — and logs the writes it would have made instead of making them.
4. Only when that log looks right, turn `dry_run` off.

## Path A — polling (recommended first)

Nothing to configure in Immich at all.

- `TRIGGER_MODE=poll` in the hub's environment.
- Run auto-lut from the catalog, or let the scheduler do it (Phase 7).

Each run asks Immich for assets newer than the cursor it stored last time, in
`/data/cache/auto_lut_state.json`. The first run has no cursor, so it will see the whole library:
keep `dry_run` on for that one, or set a narrow scope (an album, a camera model) first. `poll_limit`
caps how many assets a single run will look at.

To re-process from a point in time, edit `cursor` in that state file. To re-process an asset that
was already graded, remove its entry from `graded` in the same file — or simply change the LUT or
intensity, which produces a different output file and makes the asset eligible again.

## Path B — webhook

### 1. Allow the hub as an outbound target

Immich v3 restricts where plugins may send HTTP. **Administration → Settings → Plugins → allowed
hosts** (wording varies by release) must include the hub's host, e.g. `addons-hub:8484` when both
containers share a Docker network.

### 2. Set a shared secret

Generate one and put it in the hub's environment:

```sh
openssl rand -hex 32     # -> HUB_WEBHOOK_TOKEN
```

Restart the hub. Without it, `/hooks/immich` answers `503` rather than accepting unauthenticated
events.

### 3. Create the workflow

**Administration → Workflows → New workflow.**

- **Trigger:** `AssetCreate`.
- **Filter step:** narrow it here as well as in the addon config — for example file extension in
  `jpg, jpeg, heic`. Filtering in Immich means the hub is not woken for assets it would skip anyway.
- **Webhook step:** `POST` to
  - `http://addons-hub:8484/hooks/immich` with header `x-addons-token: <HUB_WEBHOOK_TOKEN>`, **or**
  - `http://addons-hub:8484/hooks/immich/<HUB_WEBHOOK_TOKEN>` if the step cannot send custom
    headers.

  Never put the token in a query string. The hub compares it in constant time and never logs it.

### 4. Enable the addon

The webhook dispatcher only queues addons that are **enabled** in the catalog. An event that
matches nothing returns `202` with an empty `queued` list — that is success, not silence.

### 5. Verify

Upload one photo to the dev instance and watch the hub's **Jobs** page. You should see one job that
downloads, grades, uploads, tags `addon:auto-lut`, and stacks. Upload the same photo again and the
second job should log `already graded with this LUT and intensity` without writing anything.

## When it breaks after an Immich upgrade

Symptoms and what they mean:

| Symptom | Cause | Fix |
| --- | --- | --- |
| Job log says "the webhook payload contained no asset id" | The payload shape changed | Capture the new payload and update the parser — see below |
| Immich reports the webhook step failed | Hub unreachable, or host not allow-listed | Check the allowed-hosts setting first |
| Hub returns 401 | Token mismatch | Rotate both sides together |
| Hub returns 429 | Too many events per minute from one client | Expected under a bulk import; the poll path will catch the rest |
| Something 404s | Endpoint renamed | `uv run python scripts/probe.py`, then fix `ENDPOINTS` |

To capture the new shape: the hub logs the full event into the job's log, so open the failing job
on `/jobs/{id}`, copy the payload, and replace `tests/fixtures/webhook_asset_create.json` with it.
The parser test then tells you whether `asset_ids_from_event` still finds the id.

**The committed fixture is currently synthetic** — it was written before this repo was pointed at a
running v3 server. Replacing it with a real capture is the outstanding task for this phase.

## Why the graded copy never re-triggers the addon

Four independent guards, any one of which is sufficient:

1. the copy carries `addon:auto-lut`, and anything tagged `addon:*` is skipped;
2. its filename is `auto-lut_<source-id>_<hash>.jpg`, and that pattern is skipped;
3. the source asset id is recorded in the state file, and a source that already has a copy is
   skipped;
4. it is a JPEG we produced, so the scope filters would have to admit it *and* 1–3 would all have
   to fail.

A feedback loop therefore needs four simultaneous failures, not one.
